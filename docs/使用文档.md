# 黑桃七博客使用文档

本站使用 Astro 7 静态生成页面，以 Markdown 管理文章，通过 GitHub Actions 部署到 GitHub Pages。不需要数据库或后台服务。

## 1. 本地运行

推荐 Node.js 24 LTS，最低要求为 22.12.0。项目使用 npm，Actions 根据 `package-lock.json` 安装依赖。

```powershell
npm ci
npm run dev
```

开发服务器使用 `astro dev --background` 在后台运行。管理命令：

```powershell
npm run dev:status
npm run dev:logs
npm run dev:stop
```

通过 status 或日志查看实际端口，默认是 `http://localhost:4321/`。已有服务器占用端口时可能选择其他端口。

构建与检查：

```powershell
npm run check
npm run build
npm run verify
npm run preview
```

`check` 检查类型与 Astro 模板；`build` 验证文章字段并输出 `dist/`；`verify` 检查生成页面的站内链接、图片、目录锚点和元信息；`preview` 预览构建产物。

## 2. 修改站点信息

导航栏右侧的月亮 / 太阳按钮可以切换暗黑与浅色主题。首次访问默认跟随系统，手动选择后会保存在当前浏览器，并在刷新和跳转后继续使用；不同标签页会同步选择。清除本站本地存储中的 `seven-spades-theme` 后，会重新跟随系统。主题样式在 `src/styles/theme.css`，初始化脚本在 `src/layouts/Layout.astro` 的 head 中，以减少首次加载时的主题闪烁。

编辑 `src/config.ts`：

| 字段 | 含义 |
| --- | --- |
| name / englishName | 中文站名、英文标识 |
| author | 文章作者 |
| description | 网站默认介绍与 SEO 描述 |
| email | 邮箱地址，填写地址本身，不带 mailto: |
| github | GitHub 个人页或仓库的完整 HTTPS 链接 |
| videoChannel | 视频频道的完整 HTTPS 链接 |

联系信息默认留空，前台显示“联系方式待补充”，不会生成虚假链接。首页介绍文案在 `src/pages/index.astro`，About 文案在 `src/pages/about.astro`。修改站名后也应更新 `public/images/share.png` 分享封面（1200 × 630）；`share.svg` 是可编辑的设计源文件。

## 3. 发布文章

### 按语言目录发布

文章分别放入三个目录，文件名相同表示同一篇文章的不同语言版本：

```text
src/content/blog/
├── zh-cn/
│   └── my-first-guide.md
├── zh-tw/
│   └── my-first-guide.md
└── en/
    └── my-first-guide.md
```

| 文件路径 | 网站地址 |
| --- | --- |
| zh-cn/my-first-guide.md | /blog/my-first-guide/ |
| zh-tw/my-first-guide.md | /zh-tw/blog/my-first-guide/ |
| en/my-first-guide.md | /en/blog/my-first-guide/ |

语言由目录决定，不需要额外 lang 字段。每个文件独立填写标题、摘要、正文、日期、分类、标签、封面和视频链接。只准备好一种语言也能发布，不必创建另外两份文件。

同名文件用于匹配语言版本。文章页语言菜单和 hreflang 只展示已有且非草稿的版本；没有译文时不会自动生成或回退到简体文章。首页、精选、分类、标签和 RSS 只读取当前语言的文章。英文或繁体目录为空时对应页面显示空状态。

现有四篇教程只保存在 zh-cn，正文未修改，原有简体地址保持不变。本站不会自动翻译文章的标题、摘要、正文、代码、配图或标签。你可先写好三份内容，再放入对应目录。

公共界面（导航、分类说明、按钮、空状态等）继续使用语言字典：英文在 src/i18n/en.json，繁体通过 OpenCC 转换。文章不需要写进这个字典，英文界面覆盖检查会跳过作者内容。

切换语言保留当前文章与查询参数；如果三份正文的目录标题不同，锚点也会不同，建议在正文中为对应章节显式指定相同 id。分类页可切换全部语言；标签详情页只提供存在相同标签名称的语言版本，不要求不同语言的标签用相同名称。

三种语言分别提供 RSS，Sitemap 仅列出实际发布的文章版本。没有 JavaScript 也能通过语言菜单链接切换。

开发时可运行 `npm run test:content`：它会创建临时测试文章，验证语言目录、切换匹配、单语言发布、草稿、原文保留和 GitHub Pages 子路径，再自动清理临时文件并恢复正常构建产物。

在 `src/content/blog/zh-cn/` 创建 `my-first-guide.md`，用以下模板开始。文件名推荐使用小写英文与连字符，避免发布后改名导致旧链接失效。

```yaml
---
title: 我的第一篇教程
description: 一两句话说明读者能完成什么。
publishedAt: 2026-10-13
updatedAt: 2026-10-13
category: network-check
tags: [DNS, 配置指南]
featured: false
draft: true
# cover: images/my-first-guide/cover.png
# video: https://www.youtube.com/watch?v=真实视频ID
---
```

在这段 frontmatter 后面写正文：

````markdown
本文的学习目标与适用版本。

## 准备条件

- 安装工具。
- 准备测试环境。

## 操作步骤

### 第一步

![设置界面及要点击的位置](/images/my-first-guide/step-1.png)

```javascript
console.log('hello');
```

## 验证结果

说明预期结果，以及失败时如何判断。

## 常见问题

列出容易遇到的问题。
````

字段规则：

- `title`、`description`、`publishedAt`、`category` 必填。
- `updatedAt` 可省略，但不能早于发布日期。
- `draft: true` 的文章不会出现在页面、RSS、Sitemap 或分类标签中。草稿仍会被字段校验。
- `featured: true` 的文章会进入首页精选区，最多显示 3 篇，按发布日期倒序。
- 首页最新文章最多显示 6 篇；全部文章可从分类页访问。
- `video` 可省略。填写 YouTube 视频链接后，会在文章标题下方、正文之前显示播放器，可以直接播放；其他 HTTP/HTTPS 视频链接显示观看入口。
- `cover` 是 `public/` 下的相对路径，不写 `public/`，例如 `images/my-first-guide/cover.png`。推荐 800 × 450 图片。不填则显示分类主题封面。
- 日期用于排序与展示，不是定时发布。未来日期的文章也会发布；未准备好的内容请保持草稿。

完成编辑后，将 `draft` 改为 `false`，运行检查和构建，再提交 GitHub。

### 在文章开头添加 YouTube 视频

在 Markdown 顶部的 `---` 配置区添加 `video`，无需在正文里写 iframe：

```yaml
---
title: 我的教程
description: 教程摘要
publishedAt: 2026-10-13
category: network-check
video: "https://www.youtube.com/watch?v=你的视频ID"
---
```

支持普通 watch 链接、`https://youtu.be/视频ID` 分享链接，以及 Shorts、live、embed 链接。视频 ID 是链接中的 11 位标识，不是整段链接。直接复制 YouTube 的分享链接即可，例如带 `?t=90` 的链接会从第 90 秒开始。

播放器适配手机和暗黑模式，点击播放后观看，不自动播放。每个语言版本可以填写自己的视频链接。不填 video 时不显示视频区域；正文与配图仍正常展示。

播放器需要访问 YouTube。若视频禁止站外嵌入、已删除、设为私密或当前网络无法访问 YouTube，页面内可能无法播放，可以使用播放器下方的“在 YouTube 打开”链接。

## 4. 分类与标签

四个分类值固定为：

| category | 中文分类 |
| --- | --- |
| proxy-ip | 代理 IP |
| network-check | 网络检测 |
| browser-fingerprint | 浏览器指纹 |
| ecommerce-tools | 跨境电商工具 |

标签通过 `tags` 自动生成，不需手工创建页面。相同标签应保持一致写法，例如统一使用 `Chrome`，不要同时写 `chrome`。避免在标签中使用斜杠或 URL 保留符号，中文、英文、数字和连字符均适合。

新增分类需要同时修改 `src/config.ts` 的分类信息与 `src/content.config.ts` 的 category 枚举。

## 5. 图片与站内链接

将配图放到 `public/images/文章文件名/`。正文中使用 `/images/...` 根路径，构建时会自动加上 GitHub Pages 的仓库路径前缀。

正文站内链接保持你填写的目标路径，只自动添加部署 base。简体链接示例：`[代理教程](/blog/proxy-basics/)`；英文链接示例：`[Guide](/en/blog/my-first-guide/)`。引用其他语言或尚无译文的文章时，请显式填写存在的路径。不要手动加入 `/seven-spades/`；部署路径由配置统一管理。Markdown 配图会自动设置懒加载。

图片建议使用压缩后的 WebP、PNG 或 JPEG，并填写有意义的替代文字。若需要稳定的图片布局，可使用包含 `width` 和 `height` 的 HTML img 标签。代码块会高亮，浏览器允许访问剪贴板时提供复制按钮。

## 6. GitHub Pages 部署

1. 将项目上传到 GitHub 仓库，主分支使用 `main`。若使用其他分支，修改 `.github/workflows/deploy.yml` 中的两个分支配置。
2. 在仓库 **Settings → Pages → Build and deployment → Source** 中选择 **GitHub Actions**。
3. 推送代码到 `main`，或在 Actions 中手动运行 **Deploy blog to GitHub Pages**。
4. 等待 build 与 deploy 完成，从部署结果打开网站。无需把 `dist/` 提交到仓库，也无需 gh-pages 分支。

Actions 默认根据仓库推导地址：

- 普通仓库：`https://用户名.github.io/仓库名/`。
- 用户站仓库 `用户名.github.io`：`https://用户名.github.io/`。
- PR 只运行构建和链接验证，不部署。

### 自定义域名

在仓库 **Settings → Secrets and variables → Actions → Variables** 添加 `SITE_URL`，例如 `https://blog.example.com`。添加后默认 base 为 `/`。也需要在 Pages 设置中配置自定义域名，并按 GitHub 提示设置 DNS 与 HTTPS。

如果确实需要自定义子路径，可添加变量 `BASE_PATH`，例如 `/notes/`。`SITE_URL` 只填 origin，不附带仓库路径。GitHub Pages 对 DNS 与域名的配置不由这份代码自动完成。

### 本地模拟项目站路径

复制 `.env.example` 为 `.env` 并设置：

```dotenv
SITE_URL=https://your-name.github.io
BASE_PATH=/seven-spades/
```

重新构建与验证，然后预览 `http://localhost:4321/seven-spades/`。删除本地覆盖配置或将 BASE_PATH 改回 `/`，可恢复根路径。`.env` 不提交到仓库；线上以 Actions 变量为准。

## 8. 常见问题

**页面显示但图片或 CSS 404**：检查 BASE_PATH 是否与 Pages 地址一致，不要将仓库路径重复加到站内链接中。检查 Actions 构建结果。

**文章没有出现**：确认位于对应的 `src/content/blog/zh-cn/`、`zh-tw/` 或 `en/`，扩展名是 `.md`，且 `draft` 为 false。首页只显示最新 6 篇，其他文章在分类中。

**构建失败**：先看 Actions build 日志；常见原因是分类拼错、日期无效、更新时间早于发布日期或缺少配图文件。

**复制代码失败**：剪贴板 API 需要 HTTPS 或 localhost，部分浏览器权限会限制访问，可以手动选中复制。

**分享平台没有显示封面**：默认使用 1200 × 630 的 PNG 分享封面。检查 SITE_URL 是否为真实站点地址，以及封面能否公开访问；部分平台会缓存旧的分享信息。

**想增加评论、搜索或统计**：当前版本没有这些服务，不影响静态发布。后续根据真实使用需求再选择集成方式。

## 9. 上线前检查

- 替换默认网站名、作者介绍与联系方式。
- 审阅四篇示例教程；不需要的设为草稿或替换成自己的文章。
- 填写真实视频链接（如有），替换正式分享封面。
- 运行 `npm run check`、`npm run build`、`npm run verify`。
- 确认 Pages Source、部署域名与 base，发布后检查手机布局、文章配图、目录和订阅地址。

已配置 RSS `/rss.xml`、Sitemap `/sitemap.xml`、robots `/robots.txt` 和自定义 404。项目站的 robots.txt 位于仓库路径下，搜索引擎通常只读取域名根目录的 robots.txt；需要时在用户站维护根目录规则。
